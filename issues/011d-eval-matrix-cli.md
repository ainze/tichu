## What to build

Wire the tournament orchestrator into a config-driven CLI.

- Config YAML schema:
    ```yaml
    deal_pool: artifacts/deal_pool_10k.parquet  # generated by 011a
    n_deals: 100                                 # subset of the pool head, for fast runs
    agents:
      - name: random
        factory: random
        kwargs: {seed: 0}
      - name: rule
        factory: rule
        kwargs: {}
    bootstrap_iters: 1000
    seed: 0
    output: artifacts/eval_matrix.parquet
    ```
- `main(argv)` parses the config, builds agents from the registry, slices `deals[:n_deals]`, runs `run_tournament`, writes the tidy-rows Parquet to `output`, and pretty-prints the mean matrix + CI bounds to stdout.
- Copy the config into the run dir for reproducibility (same pattern as `train_bc` / `train_calls`).

## Acceptance criteria

- [ ] Smoke test: `eval_matrix` with `random` vs `rule` on 100 deals exits 0, writes a non-empty Parquet, and the printed matrix shows `rule` beats `random` by a positive margin.
- [ ] Determinism test: running the CLI twice with the same config produces byte-identical (or schema-equal + row-equal) Parquet output.
- [ ] Output Parquet has the tidy columns `agent_a, agent_b, mean, ci_lower, ci_upper, n`.
